4.4 Learning Progress APIs
Progress is lesson-based in the MVP. Only explicit Lesson completion marks contribute to lesson completion progress. Viewing a lesson updates last-visit history but does not automatically mark the lesson complete. Quiz and Assignment status is derived from assessment records.

4.4.2 View My Classes
GET /me/classes?status=ACTIVE&page=1&size=20 returns a paginated list of the Student's memberships and pending join requests. `status` filters the Class lifecycle status (`ACTIVE` or `ARCHIVED`), not the membership status; when omitted, both class statuses may appear. The default page is 1 and the default size is 20 (maximum 100). Results are ordered by class creation time descending, then most recent membership request time descending.
Each item includes class information, Tutor, `class_status`, and `membership_status`. ACTIVE and INACTIVE memberships include lesson-based progress and derived progress status IN_PROGRESS or COMPLETED; PENDING join requests have no progress. Rejected join requests are omitted. Archived classes and former members (INACTIVE memberships) appear as read-only history. The response uses the standard paginated envelope. The endpoint replaces the earlier unpaged `{class_id, status}` response; existing callers must migrate.
4.4.3 View Class Progress
GET /classes/{classId}/progress returns the visible, accessible chapter/lesson outline, each lesson's completion mark, available QuizAttempt statuses, counts of completed and eligible lessons, progress percentages, derived class status, and the first incomplete lesson as its resume target. Chapters remain display groupings. Assignment status is omitted until Submission records exist.

The progress denominator includes visible, accessible Lessons eligible for progress calculation. Hidden Chapters and Lessons are excluded. Percentages are rounded to the nearest whole number; zero eligible Lessons yields 100% progress. A class is COMPLETED only when at least one eligible Lesson exists and every eligible Lesson has been marked complete. Otherwise its status is IN_PROGRESS.
The resume target is the first incomplete eligible Lesson in content-tree order. If no incomplete eligible Lesson remains, including when there are no eligible Lessons, the target is the class outline with reason NO_UNFINISHED_TARGET. Quiz statuses are returned for visible Quiz activities from QuizAttempt records; assignment statuses are omitted until Submission records are implemented. Archived classes and INACTIVE former memberships may read progress as history; PENDING and REJECTED memberships may not.
4.4.4 Mark or Unmark a Lesson Complete
PUT /classes/{classId}/lessons/{lessonId}/completion creates or refreshes the completion mark. Request body is empty. Return 200 OK with `{ "lesson_id": "...", "completed": true, "marked_at": "..." }`.
DELETE /classes/{classId}/lessons/{lessonId}/completion removes the mark and returns 200 OK with `{ "lesson_id": "...", "completed": false, "marked_at": null }`. Deleting a missing mark is idempotent.
Only an active Student member may use these endpoints for Lessons whose Chapter and Lesson are both PUBLISHED in an ACTIVE class. This API does not mark a Quiz, Assignment, Material, or Activity as complete. Repeating PUT refreshes `marked_at`.
Important Error Cases
403 MEMBERSHIP_REQUIRED
404 CLASS_NOT_FOUND, LESSON_NOT_FOUND (including a Lesson outside the requested class)
409 CLASS_ARCHIVED, LESSON_NOT_ACCESSIBLE (the Lesson or its Chapter is hidden)
4.4.5 Record Last Visit and Resume Learning
PUT /classes/{classId}/last-visit records the latest visited Lesson for an active Student member in an active class. The Chapter and Lesson must be PUBLISHED.
Request Body
{
  "lesson_id": "65a11d55-a23c-4a65-8ccb-76b7b7c12345"
}
The system upserts the single LastVisit row for the class membership and refreshes `visited_at` on each visit. Return 200 OK with `{ "lesson_id": "...", "visited_at": "..." }`. Deleting a Lesson deletes its LastVisit row. Hiding a Lesson retains the row, but resume selection ignores it while the Lesson is hidden.
GET /classes/{classId}/resume-target returns the selected target according to this priority:
The available in-progress QuizAttempt with the latest `started_at`, if its quiz, activity, containing Lesson and Chapter remain available.
The most recently visited Lesson, if it remains visible and accessible.
The first incomplete visible Lesson in content-tree order.
If no incomplete eligible Lesson remains, return the class outline or no unfinished target.
Assignment continuation is omitted until Submission records exist. Resuming does not create a completion mark. Archived classes and INACTIVE memberships may read LastVisit and lesson resume history, but do not receive an in-progress quiz target because they cannot continue an attempt.
Important Error Cases for PUT /last-visit: 403 MEMBERSHIP_REQUIRED; 404 CLASS_NOT_FOUND or LESSON_NOT_FOUND (including a Lesson outside the requested class); 409 CLASS_ARCHIVED or LESSON_NOT_ACCESSIBLE.
Example Response — Quiz Attempt in Progress
{
  "target_type": "QUIZ_ATTEMPT",
  "target_id": "ff6b2f66-91be-46f2-9d0c-6014c10be721",
  "reason": "IN_PROGRESS_ATTEMPT"
}
Example Response — No Unfinished Target
{
  "target_type": "CLASS_OUTLINE",
  "target_id": "9e496d33-8b5e-45aa-88cf-40fc6a7a0931",
  "reason": "NO_UNFINISHED_TARGET"
}
4.4.6 View Assessment History
GET /me/assessment-history?page=1&size=20&class_id={classId}&type=QUIZ returns the caller's paginated QuizAttempt history, including attempt status, score, and feedback where applicable. Defaults are page 1 and size 20; size is capped at 100. Results sort by started_at descending, then attempt_id descending. `type=ASSIGNMENT` returns an empty page until Submission records are implemented.
Student history is filtered to the caller. A Student must not read another Student's private assessment history. Each item includes attempt_id, class_id, activity_id, activity_title, attempt_number, type, status, started_at, submitted_at, score, and feedback (null for quiz attempts in the current implementation).
4.4.7 Tutor Progress Views
GET /tutor/classes/{classId}/progress returns progress summaries for ACTIVE members of a class owned by the caller.
GET /tutor/classes/{classId}/members/{classMemberId}/progress returns the member's lesson completion marks, progress summary, assessment outcome summaries, and current mastery per SkillTopic where Adaptive Learning data exists.
Former members' records remain stored but are not included in the active-member list.
Important Error Cases
403 FORBIDDEN
404 CLASS_OR_MEMBER_NOT_FOUND






#### Database Design -- LMS-7 ###

CompletionMark
Entity: CompletionMark
Purpose: Records that a class member has marked a lesson as completed.
Attributes:
mark_id — Primary Key.
class_member_id — Foreign Key → ClassMember(class_member_id).
lesson_id — Foreign Key → Lesson(lesson_id).
marked_at
Constraints:
UNIQUE (class_member_id, lesson_id).
The lesson must belong to the class member’s class (validated by the application).
Description: The mark is set by the student. A row means the lesson is complete, and unmarking deletes the row. Progress percentages and class status are derived when viewed and are not stored.
LastVisit
Entity: LastVisit
Purpose: Records the lesson a class member visited most recently, used to resume learning.
Attributes:
class_member_id — Primary Key; Foreign Key → ClassMember(class_member_id).
lesson_id — Foreign Key → Lesson(lesson_id).
visited_at
Description: There is at most one row per class member.


#### Requirements & Use cases -- LMS-7 ###

BR-5.4 Access to content: Studying, viewing progress and Resume require Active membership and apply only to items visible under BR-3.3. In an Archived class, access is read-only (BR-2.3): marking, attempts and submissions are not allowed.

BR-5.5 — Lesson Completion Marks
Completion marks apply only to Lessons. Materials, Quizzes, and Assignments do not have separate completion marks.
Students may mark or unmark a Lesson as complete, subject to the access and class-status rules in BR-5.4.
Each completion mark records its timestamp.
Quiz and Assignment statuses are derived from their corresponding assessment records, such as QuizAttempt and Submission. Submitting or grading an assessment does not automatically create a Lesson completion mark.
Completion marks for hidden or unavailable Lessons are excluded from current progress calculations while those Lessons are inaccessible. Their stored records are retained unless an explicit data-retention rule requires otherwise.
BR-5.6 — Lesson-Based Progress and Class Status
Progress is calculated from visible, accessible Lessons, not from the total number of Lessons plus Activities.
Chapter progress is calculated as the number of completed eligible Lessons divided by the total number of eligible Lessons in that Chapter.
Overall class progress is calculated as the number of completed eligible Lessons divided by the total number of eligible Lessons in the class.
A class is Completed for a student when at least one eligible Lesson exists and all eligible Lessons are marked complete. Otherwise, its status is In progress.
When new visible Lessons are added or previously hidden Lessons become accessible, progress and class status are recalculated when viewed.
Quiz and Assignment statuses may be displayed alongside Lessons, but they do not contribute separate completion marks to lesson-based progress.
Prerequisite descriptions are informational only. The system does not determine whether a student has satisfied a class prerequisite.
BR-5.7 — Learning Order and Resume Target
Learning content is displayed in content-tree order. This order guides the student but does not prevent access to other available Lessons or Activities.
The system records the most recently visited Lesson for each ClassMember using LastVisit.
When the student resumes learning, the system selects the target in this order:
A Quiz with an in-progress attempt in the class, if that attempt remains available.
The most recently visited Lesson, if it remains visible and accessible.
The first incomplete visible Lesson in content-tree order.
If no incomplete visible Lesson remains, the system indicates that all eligible Lessons are complete and displays the class outline.
If a student needs to continue an Assignment, the system directs the student to the Lesson containing that Assignment. Assignment submission status remains available from the corresponding assessment records.
If the selected target becomes unavailable, the system recalculates the resume target.
Resuming learning does not itself mark a Lesson as complete.
BR-5.8 Tutor view: A tutor sees progress for Active members of classes they teach. Former members' data is retained but not listed.
